# @hoshinotatsuya/committed-secrets

[![npm](https://img.shields.io/npm/v/@hoshinotatsuya/committed-secrets.svg)](https://www.npmjs.com/package/@hoshinotatsuya/committed-secrets)
[![CI](https://github.com/HoshinoTatsuya/committed-secrets/actions/workflows/ci.yml/badge.svg)](https://github.com/HoshinoTatsuya/committed-secrets/actions/workflows/ci.yml)

[English](README.md) · [Changelog](CHANGELOG.md)

Гейт: в закоммиченных файлах нет литеральных секретов. Значение, попавшее в git, есть в каждом клоне и чекауте CI, и правка файла историю не чистит — секрет скомпрометирован с момента коммита.

Упрощённая проверка, видящая одну форму — значение в кавычках сразу после ключа, — пропускала 12 из 15 проверенных строк. Здесь:

- `КЛЮЧ=значение` / `КЛЮЧ: значение` без кавычек в файлах конфигурации (.env и его варианты, YAML, compose, Dockerfile, shell, .npmrc, профили оболочки, `.netrc`, `.pgpass`, `.my.cnf`, блоки кода Markdown ``` и ~~~);
- значение в кавычках в коде и JSON, `=>` (PHP, Ruby), элементы и пары `name`/`value` XML и JSON;
- ключ любой формы (`dbPassword`, `apiKey`, `secret_token`, `JWT_SECRET`, `REDIS_PASSWORD_PREVIOUS`), склеенный (`PGPASSWORD`, `accesstoken`), сокращённый (`DB_PWD`), ключи шифрования и подписи (`ENCRYPTION_KEY`, `SIGNING_KEY`), `AUTH` последним словом имени переменной окружения (`REDISCLI_AUTH`, `BASIC_AUTH`), `_auth` `.npmrc`;
- командная строка: флаги с паролем (`--requirepass`, `--password=…`, `redis-cli -a`, `sshpass -p`, `curl -u логин:пароль`, `curl -H "Authorization: Bearer …"`, `mysql -pПАРОЛЬ`, `docker login -p`, `openssl … pass:…`, `ldapsearch -w`), присваивание `KEY=…` в любой позиции (`PGPASSWORD='…' psql`, `docker run -e`, `--from-literal=password=…`, `-o user=…,password=…`), `… set token …`; exec-форма (`["redis-server", "--requirepass", "…"]`, `["CMD-SHELL", "redis-cli -a …"]`), список YAML построчно, команда в строке кода и во встроенном коде Markdown;
- base64: `auth` Docker `config.json`, `*-data` kubeconfig, схема `Basic` — декодируются и судятся по содержимому (закрытый ключ PEM или «логин:пароль»); base64 PEM (`LS0tLS1CRUdJTi…`) где угодно;
- литерал по умолчанию: подстановки `${VAR:-литерал}` и в коде — `process.env.X ?? 'литерал'`, `|| 'литерал'`, `config.get('DB_PASSWORD', 'литерал')`, `os.getenv("KEY", "литерал")`, `.default('литерал')`, `Buffer.from('литерал', 'hex')`;
- токены по форме: GitHub, GitLab (`glpat-`, `glrt-`, `gldt-` и др.), Slack, AWS, Google, Stripe `sk_live_`, npm, OpenAI, Anthropic, JWT, Yandex Cloud (`y0_`, `t1.`, `AQVN`), ключ age;
- пароль в адресе, закрытый ключ PEM и PGP, блок YAML `ключ: |` в одну строку, тег `!!str`;
- файлы UTF-16 (с BOM и без) — текст, а не двоичные.

Не находка — заглушки (полное совпадение со списком, а не префикс), подстановки и **зашифрованное хранение**: SOPS `ENC[AES256_GCM,…]`, SealedSecret `encryptedData`, шифротекст age, Maven `{…}`. Потребитель, хранящий секреты правильно, включает гейт без исключений.

Список файлов — у git (`.env` хоста не в git, и секреты в нём законны). **Значение не выводится нигде** — ни в тексте, ни в JSON, SARIF и отчёте GitLab, ни в base64-, ни в декодированном виде: в отчёт попадают ключ, длина и отпечаток.

## Установка

```bash
pnpm add -D @hoshinotatsuya/committed-secrets
```

Node.js **24 и новее** и `git` в `PATH`. Зависимостей рантайма нет. Пакет — только CLI (программного входа нет: карта `exports` закрывает `dist/*`).

## Быстрый старт

**1.** `committed-secrets.json` в корне проекта (без него — отказ: значения по умолчанию судили бы чужой репозиторий чужим порогом):

```json
{
  "minFiles": 50,
  "requiredKinds": [".ts", ".json", ".yml", ".md"],
  "fixturesPath": "committed-secret-fixtures.json",
  "deliveryPattern": "^(deploy/|docker-compose[^/]*\\.ya?ml$|(?:[^/]*/)*Dockerfile[^/]*$|\\.github/workflows/|\\.env\\.example$)",
  "serviceCodeRoot": "src/"
}
```

**2.** Законные тестовые секреты (пароли одноразовых контейнеров) — в перечень фикстур по пути `fixturesPath`, или `[]`:

```json
[
  {
    "file": "src/testing/postgres.harness.ts",
    "keys": ["POSTGRES_PASSWORD"],
    "reason": "one-off password of the throwaway test container on 127.0.0.1"
  }
]
```

**3.** Запуск:

```bash
pnpm exec committed-secrets            # CI: все файлы git в рабочем дереве
pnpm exec committed-secrets --staged   # хук коммита: то, что уйдёт в коммит
```

Обе настройки выше — файлы [`examples/`](examples), процитированные дословно; спека пакета запускает собранный CLI ровно с ними во временном репозитории git: фикстура из перечня — код 0, новый литерал `apiKey` в `src/` — код 1 в обоих режимах, и значения в выводе нет.

## Настройка

Каждое поле проверяется по типу: `minFiles` — целое число от 0 (`"1,500"` — отказ, прежде молча выключало порог), неизвестный ключ — отказ (опечатка не действует молча; `$schema` и `$comment` разрешены), `deliveryPattern` — регулярное выражение.

| ключ | обязателен | смысл |
|---|---|---|
| `minFiles` | да | нижняя граница числа просмотренных файлов: «нет находок» на выродившейся выборке ничего не доказывает |
| `requiredKinds` | да | классы файлов, которые обязаны быть в выборке (нет класса — выборка выродилась) |
| `fixturesPath` | да | перечень фикстур (ниже) |
| `deliveryPattern` | да | регулярное выражение файлов поставки (манифесты выкатки, compose, Dockerfile, CI): секрет в них — секрет прода, перечень фикстур их не освобождает |
| `serviceCodeRoot` | да | корень кода сервиса: перечень фикстур освобождает код под ним, только если он подходит под `testCodePatterns` |
| `extraPlaceholders` | нет | заглушки проекта, полное совпадение без учёта регистра (например, локальный дефолт дев-окружения `${POSTGRES_PASSWORD:-local-dev-only}`) |
| `testCodePatterns` | нет | регулярные выражения тестового кода под `serviceCodeRoot`; по умолчанию `["spec\\.ts$", "/testing/"]` |
| `baselinePath` | нет | файл базовой линии (ниже) |

## Режимы

| команда | что проверяется | где |
|---|---|---|
| `committed-secrets` | файлы git в рабочем дереве | CI |
| `committed-secrets --staged` | изменённое в ИНДЕКСЕ относительно HEAD — то, что уйдёт в коммит | хук коммита |
| `committed-secrets --staged --full` | весь индекс | хук, если нужен полный |
| `committed-secrets --history` / `--since <коммит>` | блобы истории (все ссылки / после коммита до HEAD) | первичный аудит |
| `committed-secrets <пути…>` | только эти файлы, без перечня фикстур и порога | разово |

`--format text|json|sarif|gitlab` (по умолчанию `text`), `--output <файл>` — документ машинного формата в файл (без него — в stdout, итог тогда в stderr): SARIF 2.1.0 и отчёт GitLab Secret Detection.

GitHub Actions (SARIF — в code scanning):

```yaml
secrets:
  runs-on: ubuntu-latest
  permissions: { contents: read, security-events: write }
  steps:
    - uses: actions/checkout@v5
    - uses: pnpm/action-setup@v4
    - uses: actions/setup-node@v5
      with: { node-version: 24, cache: pnpm }
    - run: pnpm install --frozen-lockfile
    - run: pnpm exec committed-secrets --format sarif --output committed-secrets.sarif
    - if: always()
      uses: github/codeql-action/upload-sarif@v3
      with: { sarif_file: committed-secrets.sarif }
```

MR в GitLab: `--format gitlab --output gl-secret-detection-report.json` и отчёт в `artifacts.reports.secret_detection`. Хук коммита (husky, lefthook, обычный `.git/hooks/pre-commit`): `pnpm exec committed-secrets --staged`.

Из подкаталога монорепозитория `--staged` и `--history` судят каталог запуска и печатают пути от него, как `git ls-files`.

Тексты сообщений — на русском; коды выхода, структура JSON/SARIF/GitLab и ключи находок стабильны.

`--staged` судит индекс мерилом ИЗ ИНДЕКСА: конфигурация, перечень фикстур и базовая линия берутся из индекса, а не с диска — запись фикстуры, добавленная на диск и не добавленная в коммит, его не освобождает. Читаются только изменённые блобы (потоком, `git cat-file --batch`); неизменённое уже прошло гейт при своём коммите, полный скан — в CI. Правка самого гейта (конфигурации, перечня, линии) в индексе включает полный скан индекса; файлы перечня фикстур читаются всегда. Порог выборки в этом режиме считается по записям индекса.

Коды выхода: `0` — секретов нет; `1` — находки или нарушения перечня фикстур; `2` — гейт не смог проверить (нет конфигурации или git, неверный аргумент или поле конфигурации, битый JSON, выборка выродилась, вывод git не поместился в буфер — с причиной ENOBUFS, а не «нет git»). «Не смог проверить» отличается и от успеха, и от находки.

## Перечень фикстур

`fixturesPath` — `[{ file, keys, reason, count? }]`: одноразовые пароли тестовых контейнеров и т.п. Запись освобождает `count` находок КАЖДОГО ключа в файле (по умолчанию одну): второй секрет под тем же ключом — снова находка. Файл поставки (`deliveryPattern`) и код сервиса вне `testCodePatterns` записью не освобождаются; запись, которой соответствует меньше находок, чем она освобождает, — отказ. Ключи находок: имя ключа, `адрес` (пароль в адресе), `PEM`, `PGP`, `токен <вид>`, флаг команды (`redis-cli -a`, `--requirepass`).

## Базовая линия

Включить гейт в репозитории с историей, не чиня всё сразу: `baselinePath` в конфигурации и `committed-secrets --write-baseline` — текущие находки записываются отпечатками (файл, ключ, отпечаток значения; значений в файле нет). Дальше гейт падает только на НОВЫХ находках; сдвиг строки находку не обновляет, новое значение под тем же ключом — новая находка. Запись линии без находки — не отказ, о ней говорится в итоге.

Отпечаток — scrypt (N=1024) от значения с солью «файл + ключ»: он лежит в отчётах CI, и подбор слабого пароля по быстрому хэшу стоил бы секунды; у scrypt — порядка миллисекунды на попытку. Отпечаток не защищает от подбора совсем слабого пароля — значение, попавшее в git, всё равно ротируется.

## Гарантии и ограничения

- **Описательное значение считается заглушкой** (решение 0.1.1): `super-secret-jwt-token` в поле секрета — слова значения называют секрет, и это не находка. Настоящий секрет в такой форме гейт пропустит; цена обратного — шум на именах полей и членах перечислений.
- `--staged` по изменённому не видит секрета, закоммиченного в обход хука: его находит CI (рабочее дерево) или `--history`.
- Онлайн-проверки валидности токена нет и не будет: это отправка секрета наружу.
- Файлы `.http`/`.rest` (заголовки запросов строками) как класс файла не распознаются: `Authorization: …` в них не судится.
- Литерал по умолчанию с переносом строки (`=` ⏎ `env.X ?? '…'`) не виден.
- Случайный литерал из одних строчных букв и цифр с расширением из перечня форматов данных (`x7k2m9q4.json`) читается как имя файла.

## Поведение при отказе

Fail-closed: нет конфигурации или она неверна, нет git, битый JSON конфигурации или перечня, выборка меньше `minFiles` или без обязательного класса, явный путь не существует, вывод git больше буфера (причина `ENOBUFS`, а не «нет git») — код 2 с причиной одной строкой. Прерванное чтение блобов (`EPIPE`) обработано, а не `uncaughtException`, который выглядел бы как «найдены секреты». Устаревшая запись перечня — отказ: освобождение не переживает то, что освобождало.

## Совместимость

- Node.js ≥ 24 и git в `PATH` (вызываются `ls-files`, `cat-file --batch`, `diff --cached --relative`, `log`); проверено на git 2.50 локально и на git раннера CI, нижняя граница версии не установлена.
- Любая раскладка репозитория, в том числе подкаталог монорепозитория; Windows не проверялся (в CI нет Windows-раннера).

## Предел

Замер `bench/capacity.cjs` (`pnpm build && node bench/capacity.cjs [корень …]`), Node 24 на ноутбуке; 0.4.0 и 0.5.0 — в одном прогоне (исторический замер).

| вход | 0.4.0 | 0.5.0 |
|---|---|---|
| код TS, 16.6 МБ | 39 МБ/с | 54 МБ/с |
| `.env.example`, 9.5 МБ | 24 МБ/с | 17 МБ/с |
| минифицированная строка 1 МБ | 92 МБ/с | 110 МБ/с |
| base64 одной строкой 2 МБ | 136 МБ/с | 141 МБ/с |
| `key=` × 260 тыс. в одной строке | 146 МБ/с | 40 МБ/с |
| `password: ` × 100 тыс. в одной строке | 17 МБ/с (50 тыс. находок) | 24 МБ/с (одна: литерал строки называется один раз) |

Весь гейт на синтетическом монорепозитории (16 тыс. файлов, 500 МБ текста; в индексе — один изменённый файл):

| режим | 0.4.0 | 0.5.0 |
|---|---|---|
| `--staged` (хук) | 20.9 с, пик памяти 1147 МБ | **0.22 с, 69 МБ** |
| рабочее дерево (CI) | 21.2 с, 879 МБ | 22.2 с, 200 МБ |

- `--staged` прежде читал весь индекс одним буфером (потолок 1 ГиБ — дальше отказ с неверной причиной «нет git»). Теперь — только изменённые блобы, потоком: цена хука не растёт с размером репозитория.
- Рабочее дерево и история читаются по одному файлу: память — один файл, а не репозиторий.
- Конфигурация сканируется медленнее (17 МБ/с против 24): каждая строка проходит правила команд и структуру YAML. Формы токенов отсекаются подстрокой до регулярного выражения.
- Катастрофического отката регулярных выражений на длинных строках нет: худшие входы (мегабайтная строка, повтор ключа без значения) линейны.

## Разработка и тесты

```bash
pnpm install
pnpm run typecheck
pnpm run lint             # biome
pnpm test                 # сборка, затем jest последовательными группами не больше 300 тестов, 2 воркера
pnpm run build
```

Набору нужен только git: спеки поднимают временные репозитории и запускают собранный CLI. Ложные находки на строках кода (`fixtures/code-forms/`) — синтетические строки той же формы, что встретились в реальной эксплуатации, вместе с комментариями и JSDoc вокруг, которые влияют на разбор.

Что покрыто:

- корпус: 36 форм утечки и 12 безопасных форм, у каждой пара «находит ровно одну, с ключом / та же форма без секрета — тишина» (`corpus.spec.ts`), плюс 56 форм 0.5.0 с той же парой (`forms.spec.ts`);
- формы токенов: у каждого вида полная длина — находка, на символ короче — тишина;
- встроенные заглушки — каждая сама по себе, рядом — она же с хвостом;
- класс файла, перечень фикстур (причина, форма записи, код сервиса, `count`), аргументы и порог выборки, ошибки git, ссылки, подмодули, двоичные файлы, UTF-16;
- `--staged` (мерило из индекса, скан изменённого), история, базовая линия, форматы;
- значение не встречается в выводе ни в каком формате: ни сырое, ни base64, ни hex, ни пароль, декодированный из base64.

Мутации — по одной (замена в исходнике, прогон, откат копией файла): 33 мутанта на прежние пробелы (пустые списки заглушек, длина причины, исключение спек и `testing/`, квантификаторы форм токенов, граница `minFiles`, явный путь, класс Dockerfile и файла без точки, блок кода Markdown, ссылки, подмодули, ошибки git, двоичный файл) и 57 на новые правила — все красные по числу упавших тестов.
